# 装机手册 · 技术员版（现场 / 远程都按这份走 · 2026-09-26）

给**在客户机器上动手的人**看。平台侧（开通、发前缀、验收）在 `开通新商户-runbook.md`。
一句话目标：装完之后要能回答三件事 —— **这是哪家、读的是哪本账、客户看到的数对不对**。

---

## 0. 开工前你手里必须有这 5 样

| # | 东西 | 从哪来 | 缺了会怎样 |
|---|---|---|---|
| 1 | `V3Agent一键安装.exe` | 平台方给（`dist\` 出） | 用旧包 = 装的是退役的 `V3Agent.exe`，点「一键安装」直接报错 |
| 2 | 商户码（如 `shiwantongda`） | 后台「商户」页开通时定的 | 填错 = 顶掉别家的在线连接，或一直 401 |
| 3 | Agent 密钥 | 开通时**只显示一次**，当场抄下来 | 只能让平台方重置，重置会把这家现在的在线连接换掉 |
| 4 | 该老板的**账套库名** + 本机 SQL Server 账号口令 | 客户方 / V3 装机的人 | 账套名填错不会报错，但客户看到的钱是另一套账的 |
| 5 | 云端地址 `ws://149.88.75.125:8000/ws/agent` | 固定值 | 出网被杀毒/防火墙挡 ⇒ 永远连不上 |

★ 一台主机带**两本账**的那位老板（2026-09-26 拍板）：**装一份、一个商户码、两本账走"账套路由"**，
不是发第二个商户码、也不是同一目录装两份。装完之后由平台方在后台把两本都登记进
「商户 → 账套清单」，技术员在这台机器上放行第二本：

```
C:\V3Agent> V3AgentGui.exe --selfcheck --config C:\V3Agent\config.json   ← 先看本机有哪几本
C:\V3Agent> python scripts\switch-db.py --allow "第一本,第二本"             ← 只登记，不切库
```

★ **千万别把同一个商户码装两份**（两个目录同名注册）：云端同名只留一条连接，
第二份会反复顶线，症状是"这家一会儿在线一会儿掉线"。

## A. 现场装机（你在客户机器旁边）

1. 双击 `V3Agent一键安装.exe`（会请求管理员权限）。
2. 填表：安装目录（默认 `C:\V3Agent`）、云端地址、**商户码**、**Agent 密钥**、
   SQL 服务器 `127.0.0.1`、端口 `1433`、**数据库=该商户账套名**、SQL 账号、SQL 密码。
   - 商户码只收小写字母开头的 2–30 位字母/数字/`-`（不能撞 `admin`/`static` 这类保留字）。
   - 四项身份/凭据**留空就不放行**，这是故意的：Agent 不再兜任何默认值。
3. 点 **「一键安装并启动」**。日志区必须出现：
   - `已写入 C:\V3Agent\config.json 和 V3AgentGui.exe（商户码 xxx，账套 xxx）`
   - `注册开机自启（任务名 V3Agent-<码>）：成功`
   - **`✓ 可以交付：现在这一台读的就是「<账套名>」这套账，且已连上云端。`**
   出现 `✗ 实测与配置不一致` ⇒ **停下**，这就是"用 A 家的名字读 B 家的账"，改 `sql.database` 重装。
   出现 `✗ 没连上云端` ⇒ 查商户码/密钥/出网，见下面故障表。
4. 点 **「现场自检」**，等它打完 ✓/✗。这份结果文件（`logs\selfcheck-<时间>.txt`）留一份，交付时发给平台方。
5. **重启一次电脑**，开机后不点任何东西，直接看 `logs\agent.status.json` 里
   `connected` 是不是 `true`。★ 这步是验证开机自启真的成立，别省。
6. 打开客户手机/浏览器上的 `http://149.88.75.125/<商户码>/` → 应到登录页 → 用平台方给的应用账号登录
   → 首页应收合计应与自检文件里的数一致。
7. 打一张单试试（打印方案在自检里那行"打印方案=N 个"，N=0 就先别承诺打印）。

## B. 远程装机（你不在现场）

1. 把 `V3Agent一键安装.exe` 发过去（微信/网盘都行，27.9MB），**5 项参数单发**（密钥和 SQL 口令不要和包同一条消息）。
2. 让对方按 A 的第 1–4 步做，只要求一句：**"点一下「现场自检」，把 `C:\V3Agent\logs` 里最新的 `selfcheck-*.txt` 发回来"**。
   那个文件是纯文本、自带 ✓/✗ 和"下一步做什么"，不需要截图、不需要远程桌面。
3. 你这边同时核对两处：后台「商户」页该行的 **实测账套** 列，以及
   `journalctl -u v3cloud | grep "Agent 上线"` 里的 `install=<指纹> host=<机器名>`。
   ★ 主机名/指纹和你预期的那台不一致 ⇒ 对方装了两份、或者拷了别人的目录。
4. 让对方重启电脑后再发一次自检文件（第 5 步的自启验证不能省）。
5. 收工前把台账（`D:\重构\每商户台账.md` 或平台方给的那份）填完发回。

## A2. 一台主机两本账的那种机器（多加三步）

这种机器一位老板自己要在两本账之间看数据，装的时候必须**两处都登记**，少一处就是"另一本读不到"：

1. 装完第一本之后，在**安装目录**跑：
   ```bat
   cd C:\V3Agent
   V3AgentGui.exe --selfcheck --config C:\V3Agent\config.json
   ```
   看自检文件里「本机账套清单」那一行：它会列出本机所有账套，
   并点名**哪些还没放行**、直接把该跑的命令写给你。
2. 照它给的建议跑（把两本都放行）：
   ```bat
   python scripts\switch-db.py --allow "当前这本,另一本"
   ```
   它会先实测"另一本在本机存在吗、是财鲸V3 的账套吗"，不合格当场拒 —— 不许你把错字母写进配置。
   ★ 改完**不用重启 Agent**（它自己会同步这一项），但云端那份清单要平台方登记，两边都齐才读得到。
3. 再点一次「现场自检」，确认那一行不再出现"没放行"，然后回平台方一句
   「本机放行：A、B」。平台方在后台看得到你放行了哪几本，不一致会挂一条待处理告警。

顺带说明，免得被客户问倒：
- **默认哪本** = `config.json` 里 `sql.database` 写的那本；登记清单不会改变它。
- 要**整台机器**改看另一本 = 控制台账套的下拉（热切换），它改的是 `sql.database`，
  手机上没手动选过账套的客户会跟着一起换过去。两本都放行之后**一般不需要热切换**，
  老板自己在手机上选就行。
- "我只想看第二本的某一张单"这种**同时看两本**：手机上就能选（首页/「我的」里的"切账套"，
  仅当云端登记了 2 本以上时出现）。★ 手机上只要选过，请求就会**明确带着库名**，
  不再受这台机器默认库漂移的影响 —— 所以热切换之后手机数字没跟着变，不是坏了，是"各看各的"。
- 两本都放行后，`--allow` 与手机端选择是两套独立的东西：客户机没放行的那本，
  手机上点了会明确报错（`DATABASE_NOT_ALLOWED`），不会静默读到别的账。

## A3. 只拷 `V3AgentGui.exe` 出去（临时排障 / 给客户看一眼）

2026-09-26 起这条路走得通了（以前只会提示"去找模板或用安装器"）：

1. 双击 exe ⇒ 它会在 **exe 同目录**自动建一份 `config.json`，窗口下方『本机配置』自动摊开。
   建出来的那份**身份与凭据全是空的** —— 开得了界面，上不了线。
2. 按顺序填：商户码 → Agent 密钥 → 账套库名 → SQL 账号 → SQL 密码（云端地址模板带着，不用敲）。
   填完先点 **「试连并列账套」**：它用表单里这组凭据只读探一次，
   连不上或本机没有财鲸V3 账套会当场说清 —— 比装完再排查省一趟。
3. 点 **「保存并应用」**。没填全时它会一条一条列出来，且『启动后台 Agent』点了也不起作用
   （故意挡的：带着默认值悄悄上线 = 用 A 家的名字读 B 家的账）。
4. 齐了再点 **「启动后台 Agent」** → 「现场自检」→ 把 `logs\selfcheck-<时间>.txt` 发回平台方。
   ★ 配置没填全时自检**也**会出这份文件（缺哪几项写在第一条），远程支持照样有东西可看。

★ 两个必须知道的限制：
- 这条路 **不注册开机自启**（那是安装器的活）⇒ 重启电脑后这一台是离线的。
  **正式交付一定走 A 节的安装器**，别拿这份 exe 当交付物。
- 也别把带 `install_id` 的 `config.json` 一起拷走（同指纹不同机 → 云端 4002 拒连）。
  只拷 exe，配置文件让它在现场自己建。

## 故障对照（症状 → 自检里哪条红 → 处置）

| 现场看到的 | 原因 | 处置 |
|---|---|---|
| `✗ 缺少必填项：sql.password` 之类 | 装机时没填全 | 补齐后重启 Agent。Agent 现在拒绝"带着默认值上线" |
| 装完 `✗ 没有 status.json` | 进程没起来 | 点「启动 Agent」；再不行看 `logs\agent.log` 最后 20 行 |
| `✗ 能否连上 SQL Server 实例` | SQL 服务没开 / TCP/IP 协议没启用 / 端口不对 | SQL 配置管理器启用 TCP/IP、重启服务、防火墙放行 1433 |
| `✗ SQL 登录（账号/口令）` | 凭据不对（不再兜 `sa/123`） | 和 V3 装机的人核对，改 `config.json` 后重启 |
| `✗ 这个商户的账套在本机存在吗` | 库名写错，或该机器上没这套账 | 用 `scripts\switch-db.py --list` 看清单，改 `sql.database` |
| `✗ 这个库是不是财鲸V3 的账套`（缺 XS/Hpdan/Khdan/No_BillID） | 那不是业务库（`AccMaster`/报表引擎库会被排除）或 V3 没装完整 | 让客户方把 V3 账套装完整再接 |
| `✗ 实测库名 DB_NAME()` 显示"实测≠配置" | 正在读另一本账 | 立刻停，按上面改库名；这条不一致时**一切数字都不可信** |
| `✗ 云端中转可达` TCP 不通 | 出网被挡 | 先让对方浏览器开 `http://149.88.75.125/`；通了还连不上就是杀软拦 exe，加白名单 |
| TCP 通但 `connected=false` | 商户码/密钥错，或同指纹被拒（4002） | 核对码与密钥；若后台出现"同名接入被拦"横幅，让平台方点「接管」 |
| `✗ 打印方案=0 个` | V3 里没有打印方案或凭据没权限 | 先交付查询，打印单独跟客户确认 |
| `agent.log` 已经很大（自检里会提示 >50MB） | 日志不轮转 | 远程排障时先让对方把日志发回来**再**清理，别直接删（事故留档在里面） |

## 四条不要做

1. **不要**把已经装好的目录整份拷给另一台机器/另一家 —— 同一个 `install_id` 上线会被云端按
   「同指纹不同机」拒连（4002），现象是"客户说打不开"，最难查。每台都用安装器重新生成。
2. **不要**在同一台机器上把同一个商户码装两份（不同目录也不行）：云端同名只留一条连接，会反复顶线。
3. **不要**只改 `config.json` 里的 `database` 就当"切到另一本账"了 —— 用 GUI 的下拉或
   `scripts\switch-db.py`，它会等在途请求空档再切、并把实测值回写。
4. **不要**为了省事在云端改密钥"碰运气"。改错一次会把在线那家锁死。

## 交付判据（三件齐全才算装完）

- [ ] 自检文件里除"后台 Agent 是否在跑"以外全 ✓，且该条在启动后也 ✓；
- [ ] 客户机**重启后** `agent.status.json` 的 `connected=true`、`database_verified=<该商户账套名>`；
- [ ] 客户手机上打开 `/<商户码>/` 登录后的应收合计 == 自检文件里的数 == 财鲸 V3 客户端的数。
